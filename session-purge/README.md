# 删除会话（Delete Session）

在侧栏每个会话行的**悬停按钮**和**「…」菜单**里加一个「删除会话」，把会话从磁盘上真正删除——不是归档，是删除。

## 删除什么

| 位置 | 内容 |
|---|---|
| 会话目录 | 会话日志的全部格式代际与 `session.lock`；连同子 agent 会话一起删除。从该会话分叉出来的独立会话不会被删 |
| 投影检查点 | 经检查点服务自己的表删除，内存与磁盘一起变，并清理 `.bak.*` / `.tmp` 残留 |
| 工作区归属 | 工作区槽位、归档集合、置顶集合，走 Workspace 注册表删除 |
| Schedule 提醒 | 绑定在该会话上的所有提醒（含已失效的） |
| Spill 文件 | 工具大输出按目标 id 精确定位的落盘文件 |
| 浏览器 Local Storage | 清理 `dsh.conversation.*`、`dsh.sidebar-right.v1.*`、`dsh.user-questions.drafts.v1.*` 等键 |

**附件字节不在删除里动**：内容寻址、跨会话去重，删一个会话时它引用的图片很可能别的会话也在用。需要回收时使用设置页的「附件回收」。

## 使用方式

- 在会话行悬停按钮或「…」菜单点「删除会话」。
- 确认框会列出将删除的会话、大小和关联提醒；确认后执行。
- 正在使用的会话会转为**延期删除**：先停止并归档，等它冷下来（通常是下次启动）自动完成。设置页的「待完成的删除」里可以取消、立即重试或查看卡住原因。
- 删除完成后会广播 `api-session/removed`，侧栏立即掉行，不需要刷新。

删除是**不可撤销**的；提交之后没有回收站。提交之前可以随时取消。

## 残留目录与附件回收

### 残留目录

日志头读不出来的目录会被 dsh 的会话发现和 `list()` 跳过，界面上看不到，也无法选中删除，但字节仍占着磁盘。

设置页的「残留目录」一栏提供手动扫描：先扫描查看数量和体积、前 5 条路径，再决定是否删除；删除时宿主会重新计算目标，浏览器从不传路径。60 秒内的目录会放过，启动时不会自动扫描。

### 附件回收

分两轮进行，全程不删除正在被引用的对象：

1. **登记候选**：只记录没有任何会话引用、且超过 7 天未修改的附件对象，不删除字节。
2. **回收**：至少隔一天后重新扫描，只删除两轮都无人引用的候选；从第二轮开始到删除完成期间，新写入的引用会撤回对应候选。

根集合是所有可读会话日志里的 `sha256:` 引用，加上 DeepSeek 适配器的上传清单 `files-v3.json`。只要有一个会话读不出来或日志扫描不完整，整次中止、一个字节都不删。

## 配置

Plugins 页可改的字段（`.volatile()`，改完立即生效）：

| 字段 | 默认 | 含义 |
|---|---|---|
| `includeDescendants` | `true` | 连同子 agent 会话一起删 |
| `removeEmptyProjectDirectory` | `true` | 项目目录里最后一个会话删掉后，把空目录也收掉 |
| `purgeSchedules` | `true` | 删除绑定的提醒 |
| `purgeSpill` | `true` | 删除工具落盘文件 |
| `spillRoots` | `[]` | 额外要扫的 spill 根（默认扫系统临时目录下的 `dsh-spill-*`） |

非易失字段只在 patch 里覆盖：`sessionsRoot` / `storagesRoot` / `attachmentsRoot` / `llmFilesPath` 默认解析 `$DSH_HOME` 下的标准布局；`recoveryDelayMs`（默认 1500，负数关闭启动恢复）。

## 安装与卸载

- **Plugins 页**：Add plugin，填 `github:Jedeiah/dsh-plugins#path:session-purge`，安装后启用。
- **`plugin_manager`**：`action: install_bundle`，`target: github:Jedeiah/dsh-plugins#path:session-purge`。
- **卸载**：Plugins 页 Remove，或 `plugin_manager` → `action: remove_bundle`，`target: @jedeiah/session-purge`。

## 保证

- **预览与执行一致**：确认时目标集发生变化会拒绝执行。
- **同一批不会删两次**：重复删除会被拒绝；两个窗口同时删同一个会话，只有一个会成功。
- **跨进程互斥**：另一个 dsh 进程正在处理同一个会话根时会报告忙碌。
- **可取消**：提交点之前取消等于什么都没发生；提交点之后只向前完成。

## 已知限制

- 正在使用的会话要等到冷下来才真正删除（通常是下次启动）；在那之前内容还在磁盘上。
- 取消延期删除时，提醒只能以新 id 重建，投递历史不在了；已经过点的一次性提醒重建不了。
- 别的会话里的引用副本删不到：`dsh-session-reference` 会把被引用会话的转录写进引用方自己的 spill，随上游清扫过期。
- 附件回收看不到客户端草稿：还没发送的草稿里引用的老图片，第二轮仍可能把它回收。
- 安装或更新插件后需要重启 dsh 才会加载新的 Host 代码。

## 兼容性

适配 dsh **0.2.2-rc.1**，不兼容更早版本。
